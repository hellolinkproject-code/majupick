## 0. 읽는 법

### 0.1 분류 원칙

- 우선순위는 **RFP 2부 §3 매트릭스의 라벨을 그대로** 따른다. 팀이 우선순위를 올리거나 내리지 않는다.

| 우선순위 | RFP 영역 | ID 접두어 |
|---|---|---|
| A. 기본 필수 | 3.1 사용자 관리, 3.2 프로젝트 관리, 3.3.1 필수 알림, 3.3.2 알림 UI, 3.4 부가 기능 | `A-` |
| B. 심화 필수 (RFP 표기: 고급 필수) | 3.5 AI 단가 분석, 3.6 계약 및 결제(3.6.4 제외), 3.7 리뷰 | `B-` |
| C. 도전 과제 | 3.3.3 선택 알림, 3.6.4 환불, 다회차 협상, 고급 추천, 관리자 정산 관리, 팀 자체 기능 | `C-` |

| 산출물 | 1부 산출물·제출 가이드 | `O-` |

### 0.2 RFP 명시 사항과 팀 결정 사항의 구분

- **수용 기준** 열은 RFP 문장에서 직접 도출한 기준만 적는다.
- RFP가 정하지 않은 세부 정책(예: '변경 제한'의 구체적 의미, 필수 프로필 항목)은 수용 기준에 넣지 않고 `→ D-xx`로 [DECISIONS.md](./DECISIONS.md)의 결정 항목을 가리킨다. 팀이 확정하면 그때 수용 기준에 추가한다.
- RFP가 "권장", "선택적", "허용"이라고 쓴 항목은 그 표현을 그대로 표시한다.
- **예상 화면/API** 열은 구현 방향을 잡기 위한 초안이다. 화면 분리와 URL은 RFP상 팀 자율이다(2부 §6).

| A-04 | 로그아웃 | 3.1.1 | 로그아웃 시 클라이언트의 토큰이 삭제된다. 서버의 Refresh Token 무효화 엔드포인트는 **RFP상 선택** (→ D-26) | 헤더 로그아웃 버튼 / `POST /auth/logout` |

| A-10 | 의뢰인 프로필 | 3.1.3 | 회사명, 사업 분야(선택형, '기타' 선택 시 자유 입력), 웹사이트를 저장할 수 있다 | 내 프로필(의뢰인) / `PUT /users/me/client-profile` |
| A-11 | 프리랜서 프로필 | 3.1.3 | 주요 활동 카테고리(선택형), 기술 스택(옵션 선택 + 커스텀 추가), 경력(년수), 시간당 단가, 포트폴리오 URL을 저장할 수 있다 | 내 프로필(프리랜서) / `PUT /users/me/freelancer-profile`, `GET /tech-stacks` |

| A-13 | 프로필 완성 유도와 복귀 | 3.1.3, 7.3 | 가입 직후 프로필 입력을 강제하지 않는다. 의뢰인의 프로젝트 등록·프리랜서의 지원 시점에 역할별 필수 프로필이 비어 있으면 프로필 입력 페이지로 이동하고, 저장 후 원래 액션으로 돌아온다 (필수 항목 → D-05) | 내 프로필 `?returnTo=` |
| A-14 | 사용자 공개 프로필 | §6 | 다른 사용자가 볼 수 있는 공개 프로필 화면이 있다 (평균 별점·리뷰 목록은 B-19) | 공개 프로필 / `GET /users/:id` |
