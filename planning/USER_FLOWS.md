## 0. 표기

- **[팀 결정]**: RFP가 정하지 않아 팀이 정해야 하는 동작(결정 전까지 추천안으로 표기)

## 1. 공통 흐름

### 1.1 이메일 회원가입·로그인

```mermaid
flowchart LR
  A[회원가입 화면] -->|이름·이메일·비밀번호·역할| B{이메일 중복?}
  B -- 예 --> A
  B -- 아니오 --> C[계정 생성<br/>비밀번호 해싱]
  C --> D[자동 로그인<br/>토큰 발급]
  D --> E[홈]
  L[로그인 화면] -->|이메일·비밀번호| F{일치?}
  F -- 아니오 --> L
  F -- 예 --> D
```

- [RFP] 가입 직후 프로필 입력을 강제하지 않는다(A-13). 가입 후 바로 홈으로 간다.
- [팀 결정] 가입 직후 자동 로그인 여부: 추천안은 자동 로그인(D-25).

### 1.2 소셜 로그인

```mermaid
flowchart TD
  A[로그인 화면<br/>Google 버튼] --> B[Google 인증 페이지]
  B --> C[서버 콜백<br/>code 교환 · ID Token 검증]
  C --> D{같은 Google sub로<br/>가입한 적 있음?}
  D -- 예 --> H[로그인]
  D -- 아니오 --> E{같은 이메일의<br/>기존 계정 있음?}
  E -- 예 --> P{비밀번호로<br/>소유 확인 가능?}
  P -- 아니오 --> X[연결 거부 안내]
  P -- 예 --> F[비밀번호 확인] --> H
  E -- 아니오 --> G[새 계정 생성<br/>역할 미지정]
  G --> R[역할 선택 화면]
  R --> M[내 프로필 또는 returnTo]
  H --> I[홈 또는 원래 가려던 화면]
```

- [RFP] 같은 이메일이면 기존 계정과 연동한다(A-06). 최초 소셜 로그인 시 역할 선택 페이지로 보낸다(A-07).
- [팀 결정] 제공자는 Google(D-23). `email_verified = true`이고 기존 비밀번호로 소유를 확인한 뒤에만 연동한다(D-24, D-72). 이메일만 같아도 자동 연결하지 않는다.
- [팀 결정] 역할을 고르지 않은 사용자는 `/select-role`로 돌려보낸다. 역할이 필요한 API는 403 `ROLE_REQUIRED`(D-73). 선택 후 가려던 경로가 있으면 그곳으로, 없으면 내 프로필로 간다.

### 1.3 토큰 재발급과 로그아웃

- [RFP] Access Token이 만료되면 Refresh Token으로 자동 재발급하고 사용자는 그대로 이용한다(A-03).
- [RFP] 로그아웃 시 클라이언트 토큰 삭제. 서버 무효화는 선택(A-04, D-26).

### 1.4 프로필 보완 흐름 (차단형 흐름의 복귀)

```mermaid
flowchart LR
  A[의뢰인: '프로젝트 등록' 클릭<br/>프리랜서: '지원하기' 클릭] --> B{역할별 필수 프로필<br/>채워짐?}
  B -- 예 --> C[원래 액션 진행]
  B -- 아니오 --> D[프로필 입력 화면<br/>?returnTo=원래 경로]
  D -->|저장| E{필수 항목 완성?}
  E -- 아니오 --> D
  E -- 예 --> C
```

- [RFP] 등록·지원 시점에 필수 프로필이 비어 있으면 프로필 입력으로 보낸 뒤 원래 액션으로 복귀시킨다(A-13, N-10).
- [팀 결정] 무엇이 '필수 프로필'인지(D-05). 추천안: 의뢰인은 회사명·사업 분야, 프리랜서는 활동 카테고리·기술 스택 1개 이상·경력·시간당 단가.
- [팀 결정] 검사 시점: 추천안은 버튼을 누르는 시점(등록 퍼널 진입 전, 지원서 작성 화면 진입 전)에 먼저 검사하고, 서버도 등록·지원 API에서 한 번 더 검사한다. 입력 중 내용을 잃지 않게 하기 위해서다.

## 2. 의뢰인 전체 흐름

```mermaid
flowchart TD
  S[회원가입·로그인<br/>역할: 의뢰인] --> P0[홈]
  P0 --> R1[프로젝트 등록 클릭]
  R1 --> PF{필수 프로필?}
  PF -- 미완성 --> PR[프로필 입력] --> R1
  PF -- 완성 --> F1[1단계: 제목·설명·카테고리]
  F1 --> F2[2단계: 모집 시작일·마감일·예산]
  F2 -. 선택 .-> AI[AI 단가 분석 → 리포트 → 예산 반영]
  AI -.-> F2
  F2 --> F3[3단계: 필요 기술 스택]
  F3 --> D1[등록 완료 → 프로젝트 상세]
  D1 --> N1[알림: 프리랜서 지원]
  N1 --> M1[지원 관리: 지원자 목록·지원서]
  M1 -->|직접 거절| X1[해당 지원 거절 + 알림]
  M1 -->|수락 + 합의 금액 입력| AC[수락<br/>다른 대기 지원 자동 거절 + 알림<br/>프로젝트: 계약 대기]
  AC --> W1{프리랜서 응답}
  W1 -- 거부 --> BK[결렬: 지원 거절<br/>프로젝트 모집 단계 복귀] --> M1
  W1 -- 동의 --> CT[계약서 자동 생성]
  CT --> SG[계약서 서명]
  SG --> PAY[에스크로 결제<br/>PG sandbox]
  PAY --> IP[프로젝트: 작업 중]
  IP --> DV[프리랜서 납품 요청]
  DV --> AP[납품 검토 → 완료 승인]
  AP --> ST[수수료 10% 차감 지급 처리<br/>프로젝트: 완료]
  ST --> RV[프리랜서 평가<br/>별점·텍스트·태그]
```

| 3 | 등록 퍼널 1~3단계 | 기본 정보 → 일정·예산 → 기술 스택. 등록 시 시작일에 따라 '모집 예정' 또는 '모집 중' | A-15, A-24 |
| 3-1 | AI 단가 분석 결과 | (선택) 2단계에서 분석 요청 → 리포트 → '예산 반영' | B-01~B-03, D-28 |
| 4 | 프로젝트 상세 | 등록 직후 상세로 이동, 수정·삭제·마감·취소 버튼 | A-16~A-18, A-27, N-09 |
| 5 | 알림 | 지원 알림 수신 → 클릭 시 지원 관리로 이동 | A-36 ① |
| 6 | 지원 관리 | 지원서 열람, 직접 거절 또는 수락 | A-31, A-32 |
| 7 | 수락 모달 | 합의 금액 입력 후 수락 → 다른 대기 지원 자동 거절, 프로젝트 '계약 대기' | B-04, A-33, A-25 |
| 8 | 내 프로젝트 / 계약서 상세 | 프리랜서의 동의를 기다림. 거부 시 결렬 처리 | B-05 |
| 9 | 계약서 상세 | 자동 생성된 계약서 확인 → 서명(체크박스) | B-06, B-07 |
| 10 | 결제 페이지 → 결과 | 양측 서명 후 '결제하기' → PG 결제창 → 서버 검증 → 프로젝트 '작업 중' | B-09, B-11 |
| 11 | 계약서 상세 | 납품 요청 확인 → 완료 승인 → 수수료 차감 지급 처리 → '완료' | B-13, B-14 |

| 상시 | 결제 내역, 내 프로젝트, 알림 목록 | 결제 내역 조회, 세부 상태 확인, 일괄 읽음 | B-10, A-28, A-38 |

## 3. 프리랜서 전체 흐름

```mermaid
flowchart TD
  S[회원가입·로그인<br/>역할: 프리랜서] --> H[홈]
  H -->|검색창·카테고리 버튼·헤더 메뉴| L[프로젝트 목록<br/>검색·필터·정렬·페이지]
  L --> D[프로젝트 상세<br/>추천 프로젝트·북마크]
  D -. 북마크 .-> BM[내 북마크] -.-> D
  D --> A1[지원하기 클릭]
  A1 --> PF{필수 프로필?}
  PF -- 미완성 --> PR[프로필 입력] --> A1
  PF -- 완성 --> AF[지원서: 자기소개·예상 단가·예상 기간]
  AF --> MA[내 지원 현황<br/>자동 이동, 상태: 검토중]
  MA --> R{의뢰인 처리}
  R -- 직접 거절 --> RJ[알림: 거절<br/>상태: 거절]
  R -- 다른 지원자 수락 --> AR[알림: 자동 거절<br/>상태: 거절]
  R -- 모집 마감 --> CL[알림: 마감<br/>상태: 거절]
  R -- 수락 --> AC[알림: 수락<br/>상태: 수락]
  AC --> OF{합의 금액}
  OF -- 거부 --> BK[결렬: 상태 거절]
  OF -- 동의 --> CT[계약서 자동 생성 → 서명]
  CT --> WP[의뢰인 결제 대기]
  WP --> WK[작업 진행]
  WK --> DV[납품 요청]
  DV --> AP[의뢰인 완료 승인]
  AP --> ST[정산 확인<br/>지급액 = 합의 금액 − 수수료 10%]
  ST --> RV[의뢰인 평가<br/>별점·텍스트·태그]
```

| 단계 | 화면 (초안) | 동작 | 요구사항 |
|---|---|---|---|
| 1 | 회원가입 | 프리랜서 역할로 가입 | A-01, A-08 |
| 2 | 홈 → 프로젝트 목록 | 헤더·검색창·카테고리 버튼으로 진입. 키워드, 카테고리, 예산, 기술, 마감일, 모집 상태 필터. 최신·마감임박·예산 높은순 정렬. 10개씩 | A-19~A-23, A-26 |
| 3 | 프로젝트 상세 | 지원자 수·상태·추천 프로젝트 확인, 북마크 토글 | A-18, A-39, A-41 |
| 4 | 지원서 작성 | 필수 프로필이 없으면 프로필 입력 후 지원서로 복귀. 같은 프로젝트 중복 지원 불가 | A-13, A-29 |
| 5 | 내 지원 현황 | 제출 직후 자동 이동. 검토중/수락/거절 추적. 처리 후에도 결과가 남음 | A-30, A-35 |
| 6 | 알림 | 수락·자동 거절·직접 거절·마감 알림 수신 | A-36 ②~⑤ |
| 7 | 금액 제안 응답 | 의뢰인이 입력한 합의 금액에 동의 또는 거부 | B-04, B-05 |
| 8 | 계약서 상세 | 자동 생성된 계약서 서명. 의뢰인 결제 완료 후 작업 시작 | B-06~B-08, B-11 |
| 9 | 계약서 상세 | 작업 완료 후 납품 요청 | B-12 |
| 10 | 계약서 상세 | 완료 승인 후 정산 정보(결제액·수수료·지급액) 확인 | B-14 |
| 11 | 리뷰 폼 | 의뢰인 평가(1회, 수정 불가) | B-15, B-17, B-18 |
| 상시 | 내 북마크, 공개 프로필 | 북마크에서 상세 진입·지원, 받은 리뷰와 평균 별점 확인 | A-40, B-19 |

**STEP 07-A 구현 (북마크·추천, A-39~A-41).** 아래 [팀 결정] 항목은 모두 제안(D-105~D-108)이며 확정되지 않았다.
- 상세(3단계): 프리랜서는 머리말 아래 "☆ 북마크하기"로 저장하고 "★ 북마크됨"을 다시 눌러 해제한다. 요청 중에는 버튼이 잠겨 빠른 연속 클릭이 반대 상태를 만들지 않는다. 저장하면 "내 북마크 보기" 링크가 나온다. 비로그인은 "로그인하고 북마크하기" → 로그인 → 같은 상세로 돌아온다(자동 저장은 하지 않음, 다시 누른다). 의뢰인에게는 버튼이 없다. 지원 영역과 따로 동작하고, 프로필을 완성하지 않아도 저장할 수 있다([팀 결정] D-106).
- 상세 맨 아래 "이 프로젝트와 비슷한 모집 중 프로젝트": 같은 카테고리이거나 기술 스택이 겹치는, 지금 모집 중인 프로젝트 최대 4개와 추천 이유. 카드를 누르면 그 상세로 간다. 없으면 프로젝트 찾기로 안내([팀 결정] D-105).
- 내 북마크(`/me/bookmarks`, 헤더 "내 북마크"): 최근 저장순 10개씩. 모집 중이고 아직 지원하지 않은 프로젝트만 "지원하러 가기"(상세의 지원 영역으로), 이미 지원했으면 지원 상태, 모집 예정은 시작일, 마감은 "모집이 마감되어 지원할 수 없습니다". 삭제·취소된 프로젝트는 목록에서 빠진다(저장 기록은 남음, [팀 결정] D-107·D-108).

## 4. 양측 상호작용 (지원 → 리뷰)

```mermaid
sequenceDiagram
  autonumber
  actor F as 프리랜서
  participant S as WorkBridge
  actor C as 의뢰인
  participant PG as PG sandbox

  F->>S: 지원서 제출
  S-->>C: 알림 ① 지원
  S-->>F: 내 지원 현황으로 이동
  C->>S: 수락 + 합의 금액 입력
  S->>S: 다른 대기 지원 자동 거절<br/>프로젝트: 계약 대기
  S-->>F: 알림 ② 수락
  S-->>F: (다른 지원자에게) 알림 ③ 자동 거절
  F->>S: 합의 금액 동의
  S->>S: 계약서 자동 생성
  F->>S: 서명
  C->>S: 서명
  S->>S: 계약 체결
  C->>S: 결제 요청
  S->>PG: 결제창 호출(sandbox)
  PG-->>S: 결제 결과 콜백
  S->>PG: 승인 검증(금액 대조)
  S->>S: 결제 완료(에스크로 보관)<br/>프로젝트: 작업 중
  F->>S: 납품 요청
  C->>S: 완료 승인
  S->>S: 수수료 10% 차감 지급 처리<br/>프로젝트: 완료
  C->>S: 프리랜서 평가
  F->>S: 의뢰인 평가
```

- [팀 결정] 서명 순서는 정하지 않는다. 양측이 모두 서명하면 체결된다.
- [팀 결정] 거래 단계 알림(동의/거부, 서명 완료, 결제 완료, 납품 요청, 완료 승인, 평가 요청)은 도전 과제 C-01이다. 필수는 아니지만, 화면 안내(계약서 상세의 상태별 버튼)로 다음 행동을 알 수 있게 한다.

- 알림은 상태 변경과 같은 DB 트랜잭션에서 만든다. 알림 저장이 실패하면 지원·선정·거절·마감도 함께 취소된다. 화면은 서버가 성공을 돌려준 뒤에만 결과를 보여 준다.
- **머리글 종 아이콘**(역할을 고른 로그인 사용자): 읽지 않은 개수 배지(100개 이상은 99+). 30초마다와 브라우저 창으로 돌아올 때 다시 확인한다. 실시간 서버가 없어 새 알림은 최대 약 30초 늦게 보인다(D-37).
- **알림 목록 `/notifications`**(로그인 필요): 최신순 20개씩, 유형(새 지원·선정·자동 거절·거절·모집 마감)·제목·문구·시각(KST). 읽지 않은 알림은 굵은 글씨·파란 테두리·"읽지 않음" 표시. 화면을 여는 것만으로는 읽음 처리하지 않는다.
  - 알림을 누르면 → 서버에서 읽음 처리(이미 읽은 알림은 생략) → 성공 후 관련 화면으로 이동. 읽음 처리에 실패하면 이동하지 않고 이유를 보여 준다. 이동 경로가 허용 목록(내부 화면 4종) 밖이면 이동하지 않고 "이 알림은 이동할 화면이 없습니다."
  - "모두 읽음" → 서버가 처리한 뒤 "알림 N개를 읽음으로 표시했습니다." 읽지 않은 알림이 없으면 버튼이 꺼진다.
  - 빈 목록 "아직 받은 알림이 없습니다.", 오류 시 메시지와 "다시 시도". 로그아웃하면 알림 캐시를 지우고, 캐시는 사용자별로 나뉘어 다른 계정의 알림이 보이지 않는다.
- **모집 마감(의뢰인)**: 내 프로젝트 목록 각 항목 또는 프로젝트 상세 "프로젝트 관리"의 "모집 마감"(실제 모집 중일 때만 보임) → 확인("검토 대기 중인 지원은 모두 자동으로 거절되고, 지원자 전원에게 마감 알림이 갑니다. 마감 후에는 다시 모집할 수 없습니다.") → "마감 확인"(요청 중 잠금) → 서버 성공 후 "모집을 마감했습니다. 검토 대기 지원 N건을 자동으로 거절했습니다. 지원자 M명에게 마감 알림을 보냈습니다." 상태는 '모집 마감', 지원자 관리의 대기 지원은 `거절됨(자동 거절 · 모집 마감)`. 실패(이미 마감 등)하면 서버 메시지.
- **마감 결과(프리랜서)**: 내 지원 현황·프로젝트 상세에 `거절됨` + "모집이 마감되어 자동으로 거절되었습니다." + 처리일, 프로젝트 공개 상태 '모집 마감'. 검색 결과에서도 '모집 마감'.
- 선정된 프로젝트(계약 대기)에는 "모집 마감" 버튼이 없고 마감 처리 대상도 아니다(선정 버튼과 마감 버튼이 함께 눌릴 수 없다: 서버에서 한쪽만 성공).

- 공개 프로필(STEP 05-C): 프로젝트 상세의 의뢰인 이름과 내 프로필의 "공개 프로필 보기"에서 들어간다. 의뢰인은 회사명·사업 분야·웹사이트, 프리랜서는 주요 분야·경력·기술 스택·포트폴리오를 보여 주고 시간당 단가·이메일은 보여 주지 않는다(D-87). 프로필을 덜 채운 사용자는 "작성 중" 안내와 함께 채운 항목만, 역할을 고르지 않았거나 없는 사용자는 "사용자를 찾을 수 없습니다"를 보여 준다(D-88). 수정은 `/me`에서만 하며 저장하면 공개 프로필에 바로 반영된다. 지원 관리(STEP 06)의 지원자 이름도 같은 화면으로 연결한다(D-89).
- 지원(STEP 06-A): 프로젝트 상세 아래 "프로젝트 지원" 영역에서 한다. 비로그인은 "로그인하고 지원하기" → 로그인 후 같은 상세로 복귀. 의뢰인에게는 지원 영역이 없다. 프리랜서는 프로필이 미완성이면 남은 항목과 "프로필 완성하러 가기"(`/me?returnTo=/projects/:id`) → 저장 후 "하던 작업으로 돌아가기"로 상세 복귀. 모집 예정·마감 프로젝트는 안내만 보인다. "지원하기" → 자기소개·예상 단가·예상 기간 입력 → 확인("수정·철회할 수 없습니다") → "지원 확정"(요청 중 버튼 잠금) → 서버가 성공을 돌려준 뒤에만 내 지원 현황으로 자동 이동(A-30). 이미 지원한 프로젝트는 상세에서 지원 상태와 "내 지원 현황 보기"를 보여 준다. 화면 표시와 관계없이 서버가 역할·프로필·실제 모집 상태·중복을 다시 확인한다(D-91). 철회는 없다(D-35).
- 내 지원 현황(STEP 06-A, `/me/applications`): 헤더의 프리랜서 메뉴 "내 지원 현황". 지원 상태(검토중·수락·거절)와 프로젝트 공개 상태, 지원일, 예산·모집 기간, 내 제안, 거절 사유, 제출한 자기소개. 삭제된 프로젝트의 지원도 남는다(A-35). 의뢰인은 "프리랜서 전용 화면", 비로그인은 로그인 화면으로.
- 지원자 관리(STEP 06-B, 의뢰인): 내 프로젝트의 "지원자 N명 관리" 또는 프로젝트 상세 아래 "지원자 관리" 영역(소유자에게만 보임). 총 지원자·상태별 개수 → 상태 필터(전체·검토 대기·선정됨·거절됨) → 지원자 카드(이름은 공개 프로필 링크, 상태와 처리 사유, 경력·기술, 제안 금액·예상 기간·지원일·처리일, 자기소개 펼쳐 보기). "제안 금액은 지원자가 적은 예상 단가이며 최종 계약 금액이 아닙니다." 안내.
  - 거절: "거절" → 확인("거절하면 되돌릴 수 없으며, 지원자 화면에 '거절됨'으로 표시됩니다.") → "거절 확정". 그 지원만 `거절됨(직접 거절)`이 되고 다른 지원과 프로젝트 상태는 그대로다.
  - 선정: "선정" → 확인("이 지원자를 선정하면 다른 대기 지원은 자동으로 거절됩니다." + 지금 대기 중인 다른 지원 수) → "선정 확정". 요청 중에는 모든 처리 버튼이 잠긴다. 서버가 성공을 돌려준 뒤에만 "○○님을 선정했습니다. 다른 대기 지원 N건은 자동으로 거절되었습니다."를 보여 주고, 다른 대기 지원은 `거절됨(자동 거절 · 다른 지원자 선정)`, 프로젝트는 '계약 대기'가 된다. 이후 "지원자 선정이 끝났습니다. 계약 체결과 결제는 별도 단계에서 진행합니다." 안내가 남고, 수정·삭제·추가 선정·거절은 막힌다. 새로고침해도 서버 결과가 그대로 보인다.
  - 선정·거절은 실제 모집 중(마감일 당일 23:59 KST까지)에만 할 수 있다(D-34 RFP안, D-95 제안). 마감·모집 예정·취소 프로젝트는 목록만 보이고 안내 문구가 나온다. 마감 시 남은 대기 지원은 일괄 거절된다(A-34, STEP 06-C, §7.1).
  - 실패(이미 처리됨·다른 지원자 선정됨 등)하면 서버 메시지를 보여 주고 목록을 다시 받는다. 화면 표시와 관계없이 서버가 소유자·상태를 다시 확인한다.
- 내 지원 결과(STEP 06-B, 프리랜서): 내 지원 현황과 프로젝트 상세의 "프로젝트 지원" 영역에 검토 대기·선정됨·거절됨이 보인다. 선정되면 "의뢰인이 이 지원을 선정했습니다 (날짜). 계약 체결은 별도 단계에서 진행됩니다.", 거절되면 사유("다른 지원자가 선정되어 자동으로 거절되었습니다." / "의뢰인이 거절했습니다." 등)와 처리일. 제출한 금액·기간·자기소개는 그대로 남는다. 결과 알림(A-36 ②~⑤)은 STEP 06-C에서 추가했다(§7.1).
- [팀 결정] 납품 요청·완료 승인·리뷰를 별도 페이지로 만들지 않고 계약서 상세에 상태별 버튼으로 통합하는 것을 추천한다. RFP 3.6.3이 허용하는 방식이고 화면 수가 줄어든다.

### 8.3 화면 이동 관계 (사이트맵)

화살표는 "이 화면에서 저 화면으로 이동할 수 있다"는 뜻이다. 점선은 조건부 이동(로그인 필요, 프로필 미완성, 액션 완료 후 자동 이동)이다.

```mermaid
flowchart TB
  HOME[홈] --> LIST[프로젝트 목록]
  HOME -->|검색창·카테고리 버튼| LIST
  LIST --> DETAIL[프로젝트 상세]
  DETAIL -->|추천 프로젝트| DETAIL
  DETAIL -->|의뢰인 이름| PUB[공개 프로필]

  HOME --> LOGIN[로그인·회원가입]
  LOGIN -.->|소셜 신규| ROLE[역할 선택]
  LOGIN -.->|로그인 성공| HOME
  ROLE -.-> HOME

  subgraph CLIENT[의뢰인]
    NEW[프로젝트 등록 3단계] -->|2단계| AI[AI 단가 분석 결과]
    AI -->|예산 반영| NEW
    NEW -.->|등록 완료| DETAIL
    MYP[내 프로젝트] --> MANAGE[지원 관리]
  end

  subgraph FREELANCER[프리랜서]
    APPLY[지원서 작성] -.->|제출 후 자동 이동| MYA[내 지원 현황]
    BOOK[내 북마크] --> DETAIL
  end

  DETAIL -->|의뢰인 소유자| MANAGE
  DETAIL -->|프리랜서| APPLY
  NEW -.->|프로필 미완성| PROFILE[내 프로필]
  APPLY -.->|프로필 미완성| PROFILE
  PROFILE -.->|저장 후 returnTo| NEW
  PROFILE -.->|저장 후 returnTo| APPLY
  PROFILE -->|공개 프로필 보기| PUB
  PUB -.->|본인만: 내 프로필 수정하기| PROFILE
  MANAGE -->|지원자 이름| PUB

  MYA --> CONTRACT[계약서 상세]
  MANAGE -->|수락 + 합의 금액| CONTRACT
  MYC[내 계약 목록] --> CONTRACT
  CONTRACT -->|결제하기| PAY[결제 페이지]
  PAY -.->|성공·실패| PAYRES[결제 결과]
  PAYRES -.-> CONTRACT
  PAYHIST[결제 내역] --> CONTRACT
  CONTRACT -->|리뷰 작성 후| PUB

  NOTI[알림 목록] -.->|클릭 시 읽음 + 이동| MANAGE
  NOTI -.-> MYA
  NOTI -.-> CONTRACT
```
