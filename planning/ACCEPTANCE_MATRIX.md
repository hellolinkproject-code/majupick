# WorkBridge 수용 기준 추적표

> 요구사항([REQUIREMENTS.md](./REQUIREMENTS.md)) ↔ 구현 모듈 ↔ API([API_SPEC_v1.md](./API_SPEC_v1.md)) ↔ 테스트의 관계를 한눈에 본다.
> 상태: 모든 행이 `설계`. 구현·테스트가 끝나면 **상태** 열을 `구현` → `검증`으로 바꾼다.
> 스프린트 = 페이즈. 스프린트 1·2 = 페이즈 1·2(기본 필수, RFP 8.1), 스프린트 3·4 = 페이즈 3·4(심화 필수, RFP 8.2).

## 0. 표기

| 표기 | 뜻 |
|---|---|
| 페이즈 | [SPRINT_PLAN.md](./SPRINT_PLAN.md)의 구현 페이즈 |
| BE 모듈 | `apps/api/src/modules/<모듈>` (router + service) 예정 이름 |
| FE 화면 | [USER_FLOWS.md](./USER_FLOWS.md) §8.2 화면 |
| 테스트 종류 | **U** 단위(Vitest), **I** API 통합(Vitest + Supertest + 테스트 DB), **E** 배포 URL 수동 시나리오 |
