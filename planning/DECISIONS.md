# WorkBridge 결정 기록

> RFP 안내: "본 RFP에 명시되지 않은 디테일은 팀 논의를 통해 자유롭게 추가하거나 결정해도 됩니다. 다만 결정한 내용과 그 근거는 반드시 회의록, PR 설명, 회고록 등에 기록해 주세요."
> 이 문서는 RFP가 정하지 않은 부분을 모아 **추천안**을 제시한다. 팀이 확정하면 상태를 `확정`으로 바꾸고 §3 양식으로 근거를 남긴다.
> **상태 값:** `확정`(STEP 02에서 초기 설계 기준으로 지정됨) · `부분 확정`(항목 일부만 확정) · `제안`(추천안, 팀 확인 전) · `확인 필요`(외부 확인 필요)
> **STEP 02 반영(2026-10-12):** D-03, D-04, D-11, D-23, D-24, D-41, D-42, D-52, D-53, D-54, D-56 확정 / D-13 부분 확정 / D-02 확인 필요 유지. 그 밖의 항목은 `제안` 그대로이며, ERD v1·API 명세 v1은 추천안을 가정하고 작성했다(바뀌면 두 문서를 고친다). 변경 이력은 §4.
> 요구사항 ID: `A-` 기본 필수, `B-` 심화 필수, `C-` 도전, `N-` 비기능 ([REQUIREMENTS.md](./REQUIREMENTS.md))

## 0. 구분 기준

| 구분 | 뜻 | 예 | 처리 |
|---|---|---|---|
| RFP 명시 | RFP가 문장으로 정한 것 | 수수료 10%, 페이지당 10개, 리뷰 수정 불가 | 요구사항 수용 기준. 팀이 바꾸지 않는다 |
| RFP 권장 | RFP가 "권장"으로 제시한 것 | 수락 시 합의 금액 입력 → 프리랜서 동의/거부, 결렬 시 계약 직전 단계 복귀 | 추천안으로 채택. 바꾸면 근거 기록 |
| RFP 위임 | RFP가 "팀 자율", "허용"이라고 쓴 것 | 소셜 제공자, 페이지네이션 방식, 납품 화면 위치, 화면 분리·URL | 이 문서에서 결정 |
| RFP 미정 | RFP가 언급하지 않은 세부 | 필수 프로필 항목, 날짜 기준 시각, 원 단위 처리 | 이 문서에서 결정 |

- **지원 누락 방지:** 마감 처리와 새 지원은 같은 프로젝트 행 잠금을 쓴다(지원은 `FOR SHARE`, 마감은 `FOR UPDATE`). 마감 트랜잭션이 끝난 뒤의 지원은 실제 상태 검사(D-91 ⑥)에서 거부되므로 "마감 후 생긴 대기 지원"이 생기지 않는다. 마감 처리 대상은 `effectiveStatus`가 `RECRUITING`이 아닌 모든 프로젝트의 `PENDING` 지원(이미 저장 상태가 `CLOSED`인 프로젝트 포함).
- **이번 단계 이전에 생긴 지원:** 알림 ①은 만들지 않았다. 06-C에서 과거 지원에 대해 알림을 소급 생성하지 않는다(중복·오래된 알림 방지).
